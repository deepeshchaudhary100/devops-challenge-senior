2. END-TO-END TRAFFIC FLOW (STEP-BY-STEP PACKET JOURNEY)
================================================================================

When you execute:
  curl http://8.234.80.72/location

Here is what happens under the hood across every millisecond:

STEP 1: CLIENT INITIATION
  - Your machine initiates a standard TCP handshake (SYN) toward 8.234.80.72 on
    destination port 80.
  - The packet header contains:
      Source IP:      <Your Public IP, e.g., 122.161.48.19>
      Destination IP: 8.234.80.72
      Port:           80

STEP 2: GCP EXTERNAL NETWORK LOAD BALANCER (NLB)
  - The IP 8.234.80.72 belongs to a GCP regional External Forwarding Rule.
  - GCP's Maglev load-balancing fabric inspects the target pool associated with
    the GKE cluster.
  - GCP continually probes the worker nodes via an HTTP Health Check on the
    dedicated health check port (e.g., port 32264 /healthz).
  - Because our Kubernetes Service is configured with:
      externalTrafficPolicy: "Local"
    GCP NLB knows exactly which node hosts the active, healthy Pod.
  - The Load Balancer forwards the packet directly to the node without modifying
    (SNAT-ing) the client's source IP.

STEP 3: VPC INGRESS & FIREWALL INSPECTION
  - The packet reaches your custom VPC: "simpletimeservice-cluster-vpc".
  - GCP Virtual Firewall checks the ingress rules:
      Rule: "k8s-fw-a6f872b04ea8c4ec0a76f1c782d54b3e"
      Action: ALLOW TCP port 80 from 0.0.0.0/0 to target tag "gke-node".
  - The packet is permitted into the node's virtual NIC (ens4).

STEP 4: NODE ROUTING & KUBE-PROXY
  - Inside the Linux kernel of the worker node, `iptables` / `kube-proxy`
    evaluates the routing rules for Service "simpletimeservice".
  - With "externalTrafficPolicy: Local", kube-proxy bypasses inter-node routing
    and immediately routes the TCP connection to the local pod endpoint:
    10.1.0.8:8080.
  - Critical: The original client IP (122.161.48.19) is completely preserved!

STEP 5: CONTAINER RUNTIME & NON-ROOT SECURITY CONTEXT
  - The Linux container network namespace delivers the packet to port 8080.
  - The pod runs as an unprivileged user: `appuser` (UID: 1000, GID: 1000).
    It has no root privileges, ensuring container escape prevention.

STEP 6: GUNICORN WSGI & FLASK APPLICATION
  - Gunicorn workers listening on 0.0.0.0:8080 accept the HTTP connection.
  - Flask processes the route:
      - Checks `request.headers.get("X-Forwarded-For")`.
      - If absent (direct L4 connection), falls back to `request.remote_addr`.
      - `request.remote_addr` is: 122.161.48.19.
  - Generates UTC timestamp: `datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")`.

STEP 7: OUTBOUND GEOLOCATION VIA CLOUD NAT (For /location or ?location=true)
  - If location is requested, the Python app calls:
      http://ip-api.com/json/122.161.48.19
  - Because GKE nodes live in a PRIVATE subnet with NO public IP, they cannot
    reach the public internet directly.
  - The packet is routed through:
      GKE Node (10.0.10.12) ──▶ GCP Cloud Router ──▶ GCP Cloud NAT
  - Cloud NAT translates the node's private IP to a temporary external NAT IP
    and fetches the geolocation details (City: Noida, Region: UP, Country: India).
  - The response is parsed into JSON.

STEP 8: RETURN RESPONSE JOURNEY
  - Flask returns HTTP 200 with Content-Type: application/json.
  - The packet travels back out through the node's vNIC directly to the client
    (Direct Server Return / DSR architecture of GCP Network Load Balancing).
  - Your client receives:
    {
      "ip": "122.161.48.19",
      "location": {
        "city": "Noida",
        "country": "India",
        "region": "Uttar Pradesh",
        "timezone": "Asia/Kolkata"
      },
      "timestamp": "2026-09-09T17:38:24Z"
    }

3. NETWORK ARCHITECTURE (VPC, SUBNETS, CLOUD NAT)
================================================================================

1. Custom VPC ("simpletimeservice-cluster-vpc")
   - Created with `auto_create_subnetworks = false` for strict network isolation.
   - Prevents GCP's default permissive firewall rules from exposing resources.

2. Subnet Topology:
   - Public Subnet 1:  10.0.1.0/24  (asia-south1)
   - Public Subnet 2:  10.0.2.0/24  (asia-south1)
   - Private Subnet 1: 10.0.10.0/24 (asia-south1) -> GKE Nodes & Pods live here
   - Private Subnet 2: 10.0.20.0/24 (asia-south1) -> Secondary private subnet

3. Secondary IP Ranges (VPC-Native / IP Aliasing):
   - `pods`:     10.1.0.0/16  -> Directly routable pod IP addresses
   - `services`: 10.2.0.0/20  -> Cluster internal service VIPs

4. Cloud NAT & Cloud Router:
   - Name: `simpletimeservice-cluster-nat`
   - Enables GKE nodes in private subnets to:
       a) Pull container images from Docker Hub.
       b) Query external APIs (such as GeoIP lookup).
       c) Receive OS security updates.
   - Blocks ALL unsolicited inbound connections from the internet to the nodes.

   - Port: TCP 80
   - Destination: 8.234.80.72
   - Source: 0.0.0.0/0 (Internet)
   - Target: GKE Worker Nodes

2. GCP Health Check Probes:
   - Ports: 80, 443, 8080, 10256, and dynamic NodePort range (30000-32767)
   - Sources:
       - 35.191.0.0/16   (Google Cloud Load Balancer probe range)
       - 130.211.0.0/22  (Google Cloud Load Balancer probe range)
       - 209.85.152.0/22 (Google infrastructure probe range)
       - 209.85.204.0/22 (Google infrastructure probe range)
   - Keeps track of node health so unhealthy nodes are removed within 8 seconds.

3. Internal VPC Communication:
   - Protocols: TCP, UDP, ICMP (0-65535)
   - Source Range: 10.0.0.0/8
   - Allows pods and nodes within the cluster to communicate freely.

4. Default Ingress Deny:
   - All other inbound traffic not explicitly permitted above is dropped by default.

5. COMPUTE & KUBERNETES ARCHITECTURE (GKE)
================================================================================

1. Control Plane (Master):
   - Fully managed by Google Cloud.
   - Master IP: 34.93.88.44.
   - Runs Kubernetes API Server, etcd, scheduler, and controller manager.
   - High availability with automatic security patches and version management.

2. Node Pool (Worker Nodes):
   - Name: `simpletimeservice-cluster-node-pool`
   - Location: Zonal (`asia-south1-a`) to prevent inter-zone egress charges.
   - Instance Type: `e2-small` (2 vCPUs, 2 GB RAM).
   - Spot/Preemptible: Enabled (`spot = true`) for ~60-70% cost reduction.
   - Boot Disk: 30 GB `pd-standard` (Standard persistent HDD, not SSD).
   - Autoscaling: min_node_count = 1, max_node_count = 2.
   - Private Nodes: Nodes have zero public IPs.

3. Kubernetes Workloads:
   - Deployment: `simpletimeservice`
   - Pod Replicas: 2 (high availability across worker nodes)
   - Liveness Probe:  HTTP GET /health on port 8080 (initial delay 10s, period 15s)
   - Readiness Probe: HTTP GET /health on port 8080 (initial delay 5s, period 10s)
   - Resource Limits:
       Requests: 50m CPU, 64Mi RAM
       Limits:   200m CPU, 128Mi RAM
   - Security Context:
       runAsNonRoot: true
       runAsUser: 1000 (appuser)

6. APPLICATION & CONTAINER RUNTIME
================================================================================

1. Base Image:
   - `python:3.12-alpine` (Minimal attack surface, lightweight ~28MB compressed).

2. Web Server:
   - Gunicorn (WSGI) with 2 workers.
   - Bound to `0.0.0.0:8080`.
   - Access and error logging piped to stdout/stderr for Cloud Logging ingestion.

3. Endpoints Implemented:
   - `GET /`:
       Returns `{"ip": "<client-ip>", "timestamp": "<UTC-ISO8601>"}`.
       100% compliant with standard challenge test suites.
   - `GET /?location=true` or `GET /location`:
       Returns `{"ip": "...", "timestamp": "...", "location": {...}}`.
       Enriches response with City, Region, Country, and Timezone.
   - `GET /health`:
       Returns `{"status": "healthy"}` (HTTP 200) for Kubernetes health checks.

7. CI/CD & TERRAFORM STATE MANAGEMENT
================================================================================

1. GitHub Actions Pipeline (.github/workflows/ci-cd.yml):
   - Triggers automatically on push to `main` or pull requests.
   - Secret Management:
       `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`: Image registry push/pull.
       `GCP_PROJECT_ID`, `GCP_SA_KEY`: Cloud provisioning authentication.
   - Pipeline Stages:
       Stage 1: Build Docker container with buildx.
       Stage 2: Tag image with both `:latest` and commit SHA (`:${{ github.sha }}`).
       Stage 3: Push to Docker Hub.
       Stage 4: Run security verification (verifies container runs as non-root).
       Stage 5: Terraform Init, Validate, Format Check.
       Stage 6: Terraform Apply with immutable image tag (`TF_VAR_container_image`).
       Stage 7: Automatically triggers rolling update on GKE without manual intervention.

   - Bucket: `simpletimeservice-tfstate-project-52f6c9e3-3da1-4320-9fa`
